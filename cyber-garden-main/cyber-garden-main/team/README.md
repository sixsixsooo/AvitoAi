# Комплект

ИИ-помощник покупателя для кейса Avito Start на хакатоне ЮФУ. Покупатель описывает покупку обычным русским языком. Помощник уточняет условия, подбирает до трёх комплектов и объясняет цену, характеристики и запас бюджета. Если комплекта нет, показывает причину и предлагает, какое условие обсудить.

В [демо для защиты](DEFENSE.md) можно увидеть распознанные условия и сравнить ответ по двум каталогам, в одном из которых продавец пытается подменить цену через описание.

## Быстрый запуск

Нужны **Python 3.10+**, **Bash** и исходящее HTTPS-соединение со шлюзом организатора. Приложение использует стандартную библиотеку Python. Устанавливать пакеты или скачивать веса модели не требуется.

### Веб-демо в Windows

Установите **Python 3.10+** и **Node.js LTS**. При установке Python включите опцию добавления Python в `PATH`. Откройте PowerShell в папке проекта и запустите:

```powershell
npm run dev
```

Откройте адрес `http://127.0.0.1:8765`, который появится в терминале. Для другого порта используйте `npm run dev -- --port 8766`. npm-пакеты устанавливать не нужно.

Для первого запуска с Gemma на новом компьютере скопируйте шаблон из корня репозитория. В Блокноте заполните `LLM_API_KEY` выданным ключом, сохраните файл и запустите демо. Адрес шлюза в шаблоне уже записан в нужном формате.

```powershell
if (!(Test-Path .env)) { Copy-Item team/.env.example .env }
notepad .env
npm run dev
```

Не публикуйте ключ и не добавляйте его в файлы репозитория. Веб-демо слушает только `localhost`; для остановки нажмите `Ctrl+C`.

Подробности индексированного режима, нагрузочных измерений и защиты собраны в [отчёте SmartSet](SMARTSET.md).

```bash
umask 077
cp team/.env.example .env
# Впишите выданный организатором ключ в LLM_API_KEY в локальном .env.
```

| Переменная | Назначение |
| --- | --- |
| `LLM_BASE_URL` | Базовый URL шлюза с путём `/v1`. Адрес организатора указан в примере |
| `LLM_MODEL` | `google/gemma-4-31B-it` |
| `LLM_API_KEY` | Индивидуальный ключ команды |
| `LLM_USER_AGENT` | Имя клиента команды, для команды 06 — `team-06/1.0` |

`./run` читает эти переменные из окружения, поэтому проверяющий может передать собственные значения. Командный доступ по данным организатора действует до 22 ноября 2026 года, 19:00 по московскому времени. Формат запроса модели, ограничения и порядок выдачи ключа описаны в [LLM_API.md](../LLM_API.md).

### Автопроверка

Из корня репозитория выполните команду организатора, подставив абсолютные пути.

```bash
./run --catalog /absolute/path/catalog.json < /absolute/path/request.json > /absolute/path/response.json
```

Открытый пример запускается с каталогом из репозитория.

```bash
./run --catalog "$PWD/data/catalog.json" < examples/01-selection/request.json
./run --catalog "$PWD/data/catalog.json" < examples/02-clarification/request.json
```

Один вызов обрабатывает всю переданную историю и пишет в stdout ровно один JSON. `ok`, `clarify` и `no_match` завершаются с кодом 0. При некорректном вводе или сбое API процесс возвращает код 2 и пишет сообщение в stderr. При продолжении диалога передайте историю целиком, включая текст вопроса помощника и новую реплику покупателя.

### Веб-демо

```bash
python3 -m buyer.demo
```

Откройте [127.0.0.1:8765](http://127.0.0.1:8765). Сервер слушает loopback. Для другого порта или каталога доступны `--port` и `--catalog`. Готовые сценарии в интерфейсе показывают подбор, уточнение бюджета и отсутствие комплекта. Вкладка «Проверка защиты» запускает сравнение двух каталогов. Команды для защиты и короткий сценарий выступления собраны в [DEFENSE.md](DEFENSE.md).

## Как устроено решение

1. **Разбор диалога.** Локальный парсер извлекает категории, город, суммы и характеристики, а менеджер диалога применяет изменения по полям. Gemma помогает с двусмысленными формулировками и ссылками на историю. Типизированные ограничения и пожелания хранятся отдельно. Подробности и сравнение качества описаны в [QUERY_PARSER.md](QUERY_PARSER.md).
2. **Подбор.** Код берёт цену, город, категорию и характеристики из полей переданного каталога. Неизвестное значение исключает товар, если пользователь ограничил эту характеристику. Условия по ширине и температуре сравниваются с точными границами, а бюджет проверяется по сумме цен в целых рублях.
3. **Ответ.** При неполных условиях программа задаёт вопросы по всем отсутствующим обязательным полям. Из допустимых комплектов она находит до трёх самых доступных. Если город и характеристики известны, но сумма слишком мала, ответ показывает минимальную цену полного комплекта и разницу. Если мешает характеристика, помощник указывает ближайшее подтверждённое значение, когда оно есть.
4. **Защита текстов.** Названия и описания продавцов исключены из запроса к Gemma и из расчёта комплектов. Название выбранного товара попадает в карточку демо как обычный текст. Ядро генерирует объяснение по цене и структурированным характеристикам. При одинаковых структурированных данных изменение текста не меняет ответ `run`.

Списки подходящих товаров сортируются по цене и ID. Очередь с приоритетом хранит ближайшие комбинации отсортированных списков, поэтому три самых доступных комплекта можно получить без полного перебора. Порядок детерминирован для одних условий и одного каталога.

### Экономия токенов и роль модели

Хакатонный CLI вызывает Gemma на каждом запросе по контракту организаторов. Веб-демо использует локальный маршрут для распознанных запросов. На сложных ходах модель получает историю с репликами, которые нужны для интерпретации. Демо показывает, использовалась ли Gemma, а после вызова отображает время и число токенов.

## Что проверяется

| Критерий организатора | Максимум | Что можно воспроизвести |
| --- | ---: | --- |
| Скрытые сценарии | 60 | Контракт запуска, все статусы, точные суммы и границы, поддержка одного товара и нескольких категорий, история диалога и произвольные ID |
| Ручная проверка | 25 | Установка без пакетов, живой вызов Gemma, уточнение бюджета, объяснение причин подбора и отсутствия совпадений |
| Защита от манипуляций | 15 | Идентичный JSON до и после подмены описаний, цена дорогого товара сохраняется, допустимый товар остаётся в подборе |

Скрытые сценарии и фактические баллы доступны организаторам. Локальные проверки и сценарии с живым шлюзом запускаются отдельно.

```bash
python3 -m unittest discover -v
# Для этого набора нужен рабочий ключ. 20 сценариев, запросы выполняются последовательно.
python3 -m tests.live
```
