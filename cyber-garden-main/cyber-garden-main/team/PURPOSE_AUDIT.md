# Назначение товара и аудит 21 ноября 2026

Исходная версия товарища — 6ff30e1. Оба сообщения воспроизведены на локальном разборе, затем исправление проверено через реальный /api/buy с Gemma.

## Исправления

* В запросе про кресло для собаки слово «покажи» после запятой попадало в список неизвестных товаров и блокировало кресло. Команды показа, связка «и» и вводные слова придаточных предложений исключены из этой эвристики.
* Запрос про стол для груминга сохраняет категорию table и назначение «для груминга собак». Конструкции «для …», «чтобы …», «на котором …» извлекаются локально, привязываются к предмету и сохраняются при ответах про город и бюджет. Новая категория завершает назначение предыдущей.
* Назначения участвуют в ранжировании пожеланий. Пояснение результата сообщает, что пригодность для специального использования не подтверждена структурированными характеристиками каталога. Gemma получает инструкцию сохранять назначение.
* Автовыбор порта использует errno.EADDRINUSE для текущей ОС. Ранее сравнение с macOS-кодом 48 ломало обработку занятого порта на Linux. Добавлена проверка границ номера порта.
* .env удалён из Git index с сохранением локального файла. .gitignore исключает его из будущих коммитов. Ключ остаётся в предыдущих коммитах и требует перевыпуска у организатора. Удаление текущего файла не отзывает ключ и не очищает историю.

## Категория и назначение

Кресло для собаки остаётся креслом, стол для груминга остаётся столом. Для ранжирования достаточно отдельного назначения. Для подтверждения профессиональной пригодности понадобятся проверенные сведения о назначении, нагрузке, покрытии и другие существенные характеристики. Учебный контракт содержит только ширину стола, регулировку кресла и температуру света лампы. Этих полей недостаточно для заключения о пригодности для груминга.

На первоначальные запросы система уточняет город и бюджет, сохраняя предмет и назначение. После «Таганрог, бюджет 15000 рублей» показывает допустимые варианты с пожеланием и оговоркой о пригодности. Мягкое назначение само по себе не исключает обычные товары. Охват всех необычных формулировок этим исправлением не доказан.

## Проверки

После возвращения этого исправления поверх фикса переключения товара прошли 131 Python-тест и 10 проверок интерфейса. Дополнительно два живых HTTP-запроса с Gemma проверили переход от комплекта к одному столу для груминга и отказ от комплекта. Получены три варианта одного стола с бюджетом 15 000 ₽, без прежнего ограничения ширины; последняя реплика вызывает уточнение вместо повторного показа. Предыдущий отдельный прогон проверял четыре живых запроса для кресла собаки и стола для груминга, включая уточнения города и бюджета.

Из корня проекта выполняются `python -m unittest discover -v`, `node tests/ui_dialogue.cjs` и `python -m bench.purpose_live`. Для модульных тестов зависимости находятся в tests/requirements.txt. Последняя команда использует реальный шлюз и локальный .env, делает четыре последовательных вызова с ограничением частоты и сохраняет bench/results/purpose-live.json.

Новые tests/test_purpose.py проверяют категории, перенос назначения между сообщениями, отмену пожелания, область действия при нескольких товарах, бюджет и ложные указания цены в описании. Существующий набор проверяет схемы CLI, пропущенные характеристики, строгие границы, ошибки шлюза, неполные ответы индекса и интерфейс. Это проверка конкретных сценариев, а не исчерпывающий пентест публичного сервиса.
